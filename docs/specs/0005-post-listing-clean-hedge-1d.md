## 0. Отношение к 0004: это НЕ ретрай

0004 убил стратегию, но диагностика показала: KILL продиктован оборотом
322-именного равновзвешенного хеджа (ежедневный ребаланс → 139k сделок, MDD 99%),
а не отсутствием сигнала. 0005 меняет ОДНУ вещь — конструкцию хеджа — по
конкретной, зафиксированной ДО данных причине (устранить измеренный артефакт).
Сетка сигнала (E_start, H) идентична 0004 для сопоставимости; N в DSR считается
заново. Это не «перебор параметров ради PASS», а исправление известной ошибки
моделирования. Если и чистая версия KILL — пост-листинговый эффект закрыт.

## 1. Гипотезы (те же H5, зафиксированы до данных)

- **H5-drift.** Молодые перпы (возраст ∈ [E_start, H]) первые недели дрейфуют
  вверх относительно рынка (приток внимания/потоков). Лонг корзины молодых.
- **H5-reversal.** Обратное: листинг-памп затухает, молодые отстают. Шорт корзины.
- Рыночная бета снимается **одним ликвидным инструментом** (BTCUSDT-перп),
  а не корзиной зрелых. Обе гипотезы в гриде; DSR штрафует за оба направления.

## 2. Что именно меняется против 0004

| | 0004 | 0005 |
|---|---|---|
| Хедж | 322 зрелых, равновес, ежедн. ребаланс | **шорт BTCUSDT, вес const** |
| Ребаланс молодых | ежедневный | **недельный (7д)** |
| Оборот хеджа | ~322 имени/бар | ≈ 0 (вес хеджа не меняется) |

Обе правки продиктованы диагностикой 0004, обе снижают оборот. Ничего в СИГНАЛЕ
не тронуто.

## 3. Данные (всё из кэша)

Панель 1d, 2024-01…2026-06, 790 перпов из S3-листинга (делистнутые включены).
Возраст = дни с первого бара. BTCUSDT обязан присутствовать (хедж). Funding
реальный на обе ноги. Пол ликвидности $2M медианного дневного объёма для молодых.

## 4. Анти-look-ahead

Первый торгуемый бар символа = листинг+1; инклюзия в корзину по данным t−1;
позиция t = веса t−1 (движок). Недельный ребаланс: состав молодых
пересчитывается раз в 7 баров, между — заморожен.

## 5. Издержки

Молодые 5 bps taker + 10 bps slippage; BTC-хедж 5 + 2 bps (ликвиден).
Стресс ×2 по slippage обязателен для PASS.

## 6. Грид (заморожен; N=6 на направление, как в 0004)

E_start ∈ {1, 3} дн; H ∈ {7, 14, 30} дн; ребаланс = 7 (fixed);
хедж = шорт BTCUSDT (fixed). 6 конфигов × 2 направления = 12.

## 7. Валидация (судья без изменений) + gross-диагностика

CPCV S=10, k=2, purge=1, embargo=30; вердикт по медианному из 9 путей net-of-cost.
DSR (точная V, N=6/напр.); PBO. Пороги прежние (сделки ≥ 200, OOS Sharpe > 0.7,
MDD < 20%, DSR ≥ 0.95). **Дополнительно** — gross OOS Sharpe (те же веса, costs=0):
диагностика «есть ли сигнал до издержек». Gross не влияет на вердикт, только на
интерпретацию (если gross > 0 сильно, а net KILL — сигнал есть, но неторгуем;
если gross ≈ 0 — эффекта нет вовсе).

## 8. Kill-критерии

KILL при провале любого порога net-путём. Для PASS: slippage ×2; плато ±1 шаг;
разбивка по годам; PBO < 0.5; суммарный N (0001-0005). Хрупкий = KILL. Стоп после
вердикта; paper/live — отдельное решение владельца.

## 9. Инженерные дельты

1. `young_vs_btc_weights()` в listing.py: молодые +dir/ny, BTCUSDT −dir, недельный
   ребаланс. Переиспользует run_listing_backtest (BTC как not-young → slip 2bps).
2. Gross-прогон = тот же матричный билд с costs=0; отдельное поле в отчёте.
3. run_listing.py: пресет/флаг --clean (хедж BTC, ребаланс 7).

## 10. Критерий успеха

Realised при вердикте обеих семей, подтверждённом устранении издержечной
патологии (оборот хеджа ≈ 0, сделок на 2+ порядка меньше 0004) и залогированной
gross-диагностике. KILL с gross ≈ 0 → пост-листинговый эффект закрыт окончательно.
KILL с gross > 0 → сигнал есть, но неторгуем на споте Binance (нужна другая
реализация/венью — уже за рамками бесплатного трека).
