## 1. Зачем (и почему не продолжаем старое)

Первый прогон убил все 16 таймсерийных ячеек (momentum / mean-reversion / breakout /
carry на BTC/ETH/SOL/BNB, 1h): после издержек и мультитест-поправки edge отсутствует.
Расширять те же гриды — data mining, запрещено предохранителем.

Этот спек — новое семейство с **другой экономической гипотезой**: сигнал не «куда
пойдёт монета», а «какая монета сильнее/дешевле в финансировании ОТНОСИТЕЛЬНО
корзины». Лонг-шорт конструкция убирает доминирующую BTC-бету — если edge есть,
он относительный, и его не может имитировать простое «рынок вырос».

## 2. Экономические гипотезы (зафиксированы ДО данных)

**H1 — XS-momentum.** Капитал в крипте ротируется между нарративами медленно:
монеты, обгонявшие корзину последние 1–4 недели, продолжают обгонять на горизонте
дней–недель (инерция внимания и потоков). Ранжируем по прошлой относительной
доходности, лонг верхний квантиль / шорт нижний, дельта-нейтрально.

**H2 — XS-carry.** Funding-ставки перпов устойчиво различаются между символами:
перегретые лонги платят шортам заметно больше медианы корзины, и это
перепозиционирование инертно (часы–дни). Шорт дорогого funding / лонг дешёвого
собирает спред ставок при примерной рыночной нейтральности.

Провал гипотез фальсифицируем: если после честной валидации медианный OOS-путь
не проходит пороги — семейство закрывается (KILL), а не перенастраивается.

## 3. Universe (point-in-time, без survivorship)

- Кандидаты: все USD-M перпетуалы Binance с историей ≥ 90 дней на дату ребаланса.
- Отбор: **топ-16** по медианному quote-объёму за предшествующие 30 дней.
- Пересмотр состава: в первый 4h-бар каждого календарного месяца, только по данным,
  доступным до этого момента.
- Делистнутые символы остаются в истории тех месяцев, где они были в топе
  (данные с data.binance.vision сохраняются для делистнутых). Если на имплементации
  выяснится, что дампы делистнутых недоступны, — это фиксируется в отчёте как
  survivorship-bias, а не замалчивается.

## 4. Сигналы и грид (полный, пере-регистрированный; N честно идёт в DSR)

Таймфрейм: **4h**. Решение на закрытии бара t → исполнение на открытии t+1
(анти-look-ahead как в harness). Дельта-нейтрально: суммарный вес лонгов = +0.5,
шортов = −0.5 (гросс 1.0), равновзвешенно внутри стороны.

**XS-momentum (24 конфигурации):**
- lookback L ∈ {42, 84, 180} баров (~7, 14, 30 дней);
- skip s ∈ {0, 6} баров (пропуск последнего дня против краткосрочного реверса);
- квантиль q ∈ {25%, 33%} (число имён на сторону из 16: 4 или 5);
- ребаланс R ∈ {6, 42} баров (~раз в день / раз в неделю).
  Итого 3 × 2 × 2 × 2 = 24.

**XS-carry (12 конфигураций):**
- окно среднего funding F ∈ {18, 42, 84} баров (~3, 7, 14 дней);
- квантиль q ∈ {25%, 33%};
- ребаланс R ∈ {6, 42} баров.
  Итого 3 × 2 × 2 = 12.

Никаких добавлений конфигураций после первого взгляда на результаты. Если грид
меняется — новая версия спеки, счётчик N для DSR начинается заново с объединения.

## 5. Издержки и funding

- Тейкер 5 bps + слиппедж 2 bps на сторону **на каждую ногу** (оборот считается
  по Σ|Δw_i| в каждом ребалансе).
- Funding: реальная история по каждому символу, floor-выравнивание к бару
  (как в `harness/data.py` после фикса ms-джиттера). Позиция платит/получает
  по знаку (лонг платит положительную ставку).
- Carry-результаты без реального funding = недостоверны, прогон невалиден.

## 6. Протокол валидации (тот же судья, без изменений)

- Окно данных: последние 24 полных месяца на дату прогона.
- **CPCV**: S=10 групп, k=2, purge=1 бар, embargo=max lookback конфигурации;
  вердикт по **медианному** из C(9,1)=9 полных OOS-путей; worst path — в отчёт.
- **DSR** с точной trial-variance; N = 24 (momentum) и 12 (carry) отдельно
  на семейство; если сравниваются оба семейства — N=36 для любого выжившего.
- **PBO** (CSCV, 10 блоков) по матрице конфигураций.
- Пороги — без изменений (`runner.py: Thresholds`): OOS-сделок ≥ 200
  (смена веса ноги = сделка), OOS Sharpe > 0.7, MDD < 20%, DSR ≥ 0.95.

## 7. Kill-критерии и стресс выжившего

KILL немедленно, если медианный путь не проходит любой порог. Для PASS-кандидата
дополнительно (Этап 3 протокола): параметрическое плато ±1 шаг по каждому
параметру; разбивка по годам (2024H2 / 2025 / 2026H1) — не должно быть
отрицательных OOS во всех режимах разом; удвоение издержек не переворачивает
вердикт; PBO < 0.5. Хрупкий кандидат = KILL с формулировкой «хрупок».

## 8. Инженерные дельты в harness (без изменения судьи)

1. Панельный загрузчик: N символов × 4h с parquet-кэшем + funding по каждому.
2. Point-in-time universe builder (объёмы → топ-16 на месяц).
3. Кросс-секционный signal builder: веса w_i(t) из рангов (вместо {-1,0,+1}
   одного символа).
4. Портфельный backtest: r_p = Σ w_i·r_i, издержки на Σ|Δw_i|, funding по ногам.
   Судья (runner/DSR/CPCV/PBO) не трогается.

## 9. Вне скоупа

Ликвидационные каскады, межбиржевой basis, деривативы вне Binance USD-M,
paper/live-трейдинг (запрещён до робастного PASS + отдельного решения).

## 10. Критерий успеха спеки

Спека считается `realised`, когда прогон по ней дал вердикт (PASS или KILL) при
валидном funding и ≥ 75% валидных ячеек. KILL — тоже успех: гипотезы H1/H2
закрываются числами, дальше — следующая гипотеза, не перекрутка этой.
