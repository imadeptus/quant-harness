# FINDINGS — Калибровка судьи (исследование детекционной силы)

**Статус:** realised · 2026-07-24 · движок `harness/calibration.py`, отчёт
`reports/CALIBRATION.md` (пересборка: `python run_calibration.py --seeds 200`).

## Зачем это нужно

Каждый вердикт, выданный проектом, был KILL (10 спек × 3 венью, KILL-1..8). Этому
можно доверять только если судья — *откалиброванный детектор*, а не заклинивший
null-автомат. `test_detection_power.py` уже доказал: судья *способен* выдать PASS
на сильной стратегии и KILL на шуме — на двух точечных примерах. Это исследование
картирует **всю поверхность отклика** на синтетике с известной истиной, так что
каждый KILL теперь читается против *измеренного* уровня ложных срабатываний и
*измеренного* порога детекции — а не надежды, что судья «вроде работает».

Метод: подать в CPCV-судью (`run_cpcv_returns`) синтетические (N конфигов × T
баров) матрицы из известных data-generating processes; каждый конфиг —
**независимый** draw из одного и того же DGP (адверсариальный выбор —
независимость максимизирует in-sample selection luck, самый тяжёлый случай для
Deflated Sharpe). 200 Monte-Carlo seed на ячейку, 912 дневных баров, волатильность
бара 0.01, CPCV(10, k=2, purge=1, embargo=5), пред-зарегистрированные
`Thresholds()`. Гейт по числу сделок сознательно выполнен, чтобы исследования
изолировали именно *статистический* детектор (Sharpe / DSR / drawdown).

## Главные результаты (200 seed)

| свойство | результат | как читать |
|---|---|---|
| **False positive rate** (шум, N=6) | **0.0%** PASS, медианный DSR 0.07 | судья не пропускает шум |
| **Порог детекции** | PASS≥50% при истинном годовом Sharpe **~2.2**, ≥90% при **~3.0** | честная планка, которую обязан взять реальный edge |
| **Издержки** | gross ann-Sharpe-3 edge держит PASS≥50% до ~0.001/оборот; умирает к 0.004 | net убивает gross — ровно паттерн проекта |
| **Множественное тестирование** | истинный ann Sharpe 2: PASS 82%→16% при росте N с 1 до 100; медианный DSR 0.999→0.510 | дефляция активно защищает |
| **Толстые хвосты** (df=3, нулевой edge) | 0.0% FPR; мощность на реальном edge сохраняется (86–91%) | поправка PSR/DSR на не-нормальность держит |
| **Автокорреляция** (φ до 0.6, нулевой edge) | FPR остаётся ≤1% | опасавшийся failure mode **не материализовался** |
| **Смена режима** (edge жил часть выборки) | PASS 91% (жил 100%) → 6% (жил 25%) | судья не экстраполирует умерший edge |
| **Объём данных** (истинный ann Sharpe 2) | PASS 10% при 250 барах → 77% при 1825 барах | мощность растёт с длиной серии; даже Sharpe-2 нужны годы дневных данных |

Полная кривая мощности (PASS-rate против истинного годового Sharpe):

```
ann Sharpe  0.0  0.5  1.0  1.5  2.0  2.5  3.0  3.5  4.0
PASS rate    0%  1.5% 8.5% 30%  46%  81%  97%  99% 100%
```

## Единственный вывод, который имеет значение

Лучший out-of-sample результат, который проект когда-либо выдал — **net Sharpe
~0.88** (спека 0002 `xs_momentum`, сама по себе KILL). Измеренный 50%-порог
детекции — **~2.2**. При ann Sharpe ~0.9 судья выдаёт PASS примерно в **5–8%**
случаев.

Значит, весь KILL-рекорд лежит далеко ниже пола детектора: наблюдённые edge
согласуются с гипотезой **«edge детектируемой величины отсутствует»**, а не с
судьёй, который отказывается говорить PASS. Порог детекции (~2.2) совпадает с
пред-зарегистрированной интуицией, записанной в `NEXT_SESSION.md` («Планка PASS:
реальный OOS Sharpe ~2.2+») — записанной ещё до этого исследования. Независимое
подтверждение.

## Два вывода, которые стоит запомнить

1. **Автокорреляция обработана, и вот *почему*.** Положительная серийная
   корреляция раздувает наивный Sharpe, занижая дисперсию среднего — классическая
   ложь бэктеста. Судью это не обмануло (FPR ≤1% при φ=0.6). Механизм виден в
   таблице: медианная просадка *растёт* с φ (0.31 → 0.49), так что drawdown-гейт
   становится второй линией обороны именно там, где Sharpe-гейт под наибольшим
   давлением. CPCV purge/embargo и DSR вносят вклад оба.

2. **При N=1 судья — номинальный тест уровня ~5%.** С одним конфигом нет
   множественного тестирования, поэтому DSR вырождается в PSR — односторонний
   тест с порогом 0.95, чей false-positive rate на шуме — номинальные ~5%, а
   медианный DSR по симметрии — ~0.5. Это корректно, а не утечка. Каждый реальный
   грид в проекте имел N≫1, что увело эффективный FPR к ~0 (см. таблицу null: 0%
   при N≥6). Вывод: **единственный** пред-зарегистрированный конфиг — самая
   *слабая* конфигурация этого судьи; предпочтителен небольшой честный грид, чтобы
   дефляция могла работать.

## Ограничения (честно)

- **Синтетика, i.i.d.-модель конфигов.** Конфиги — независимые draws из одного
  DGP. Реальные гриды стратегий имеют *коррелированные* конфиги (соседние
  параметры делят доходности), что снижает эффективное число trials — значит
  реальная дефляция, если и отличается от смоделированной здесь, то мягче. Это
  исследование ограничивает адверсариальный случай, не типичный.
- **PBO приглушён намеренно.** Все конфиги делят один edge, поэтому нет «неверного
  конфига, на который можно переобучиться»; PBO держится около ~0.5 на всём
  протяжении и приводится только как вторичная диагностика. PBO различает, когда
  конфиги отличаются по истинному качеству — а это ровно случай реального грида,
  описанный выше.
- **Пороги — пред-зарегистрированные.** Это исследование характеризует судью *как
  он сконфигурирован*; оно не подстраивает пороги задним числом (это было бы тем
  самым переобучением, против которого весь харнесс существует).

## Итог

Судья — откалиброванный детектор: ~0% ложных срабатываний под множественным
тестированием, гладко растущая мощность до порога детекции ~2.2, устойчивость к
толстым хвостам, серийной корреляции и нестабильности режима, корректная
чувствительность к издержкам. Равномерный KILL-рекорд проекта — поэтому
**свидетельство о проверенных рынках, а не артефакт сломанного судьи.** Ключевое
утверждение — «метод валиден» — теперь опирается на измеренную поверхность
отклика, воспроизводимую одной командой.
