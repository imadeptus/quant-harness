# quant-ai-lab

Исследовательская лаборатория одного вопроса: **есть ли торгуемый edge на
крипто-перпетуалах, который выдерживает честную проверку?** Не «сделать бота», а
получить вывод, который нельзя подделать самообманом.

**Ответ получен.** 10 пред-зарегистрированных гипотез × 3 венью (Binance, Bybit,
Hyperliquid), таймсерийные / кросс-секционные / событийные сигналы — **все KILL**.
Предсказательной альфы на публичных данных нет. Единственный найденный
положительный денежный поток — сбор funding на неэффективной венью (~7%/год
«реалистично» — оценка по бэктесту), и это управление хвостовым риском, а не
альфа. Это настоящий вывод, а не тупик.

И — что важнее для доверия к выводу — **метод измерен**: судья, выносящий каждый
вердикт, прогнан по всей поверхности решения на синтетике с известной истиной.
False-positive на шуме — 0%. Порог детекции — ~2.2 годового Sharpe. Лучший net
Sharpe, который проект вообще наблюдал (0.88), лежит ниже половины этого порога →
поток KILL — это свидетельство *о рынках*, а не заклинивший детектор.

Именно этот детектор — и дисциплина пред-регистрации за ним — и есть то, что репо
продаёт: механический, откалиброванный вердикт PASS/KILL в виде CLI,
Python-библиотеки или hosted API — для всех, кому нужна независимая проверка
доходностей стратегии до того, как выделен капитал. См. **Что продаётся** ниже.

## Быстрый старт

```bash
cd quant-harness
pip install -e ".[dev,api]"
python -m pytest                  # 198 тестов (с extras dev+api), включая калибровочные гарды
python examples/quickstart.py     # KILL на шуме / PASS на edge, без данных
qh-audit --returns examples/audit_sample_returns.csv --trials 20   # PASS/KILL-вердикт по CSV
```

## Что продаётся

Результат лаборатории — не торговый сигнал, а **инструмент вердикта**,
построенный, чтобы честно этот сигнал проверить. Два способа использования:

- **`qh-audit`** — CLI и Python-библиотека: CSV доходностей по периодам →
  механический вердикт PASS/KILL (Combinatorial Purged CV, Deflated Sharpe, PBO,
  четыре пред-зарегистрированных гейта) плюс Markdown/JSON-отчёт. Работает
  локально, без сетевых вызовов.
- **Hosted verdict API** (`quant-harness/api/`) — тот же судья за FastAPI-сервисом
  (`POST /v1/verdict`): загрузи матрицу доходностей — получи по HTTP вердикт,
  метрики, чувствительность к издержкам и короткий отчёт. Сделан так, чтобы
  AI-агент мог запросить независимую проверку так же просто, как человек.

**Для кого:** аллокаторы, prop-деск, маркетплейсы ботов и разработчики
AI-агентов, которым нужен независимый откалиброванный вердикт по доходностям
стратегии — своей, вендора или контрагента — до того, как выделен капитал.

**Чем это не является:** не генератор сигналов, не торговая рекомендация, не
обещание доходности. KILL означает «не видно на этих данных, при этих
издержках, после поправки на число перебранных конфигураций», а не «прибыли нет
нигде». Полная картина — включая границы того, что PASS означает и чего не
означает, — в `quant-harness/README.md`.

## Почему этому можно верить

1. **Дисциплина, доведённая до вывода.** 10 честных пред-регистраций, ни одна не
   «дожата» до PASS. Большинство ритейл-бэктестов ломаются на первом же из семи
   способов самообмана; здесь закрыты все семь — конструктивно.
2. **Зрелый инструмент.** `quant-harness` — переиспользуемый honest-backtest
   фреймворк: leakage-safe WFA/CPCV, реалистичные издержки, Deflated Sharpe, PBO,
   механический вердикт — с доказанной и *измеренной* детекционной силой (см.
   Навигацию выше).
3. **Честный отрицательный результат — тоже результат.** «Edge не видно на этих
   данных с этими издержками» — знание, которое экономит капитал; и оно записано
   как KILL, а не подано как «почти получилось».
4. **Исследовательский результат по funding-harvest раскрыт честно.** Живой
   paper-трек (запущен 2026-07-22, cron/launchd, без капитала под риском) сейчас
   в минусе — около −1.5% за шесть недель, примерно −13%/год в годовом выражении —
   против ~7%/год «реалистичной» оценки по бэктесту. Показаны оба числа; ни одно
   не рекламируется как доходность, которую стоит ожидать.
